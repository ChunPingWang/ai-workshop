# new-pay Portal User Stories

需求來源：`new-pay_Portal_SRS.md`。本文件以使用者可觀察的操作與結果描述驗收條件；端點、資料表、傳輸格式等技術規格列於 [SD.md](SD.md)。

## COM 共用功能

### US-COM-01 使用 Portal 功能
**身為** Portal 使用者，**我想要** 登入後進入功能頁並能登出，**以便** 在需要時開始或結束工作。

| | |
|---|---|
| SRS 章節 | 3.1 |
| 涵蓋條文 | P-COM-01, P-COM-03, P-COM-04, P-COM-05 |
| 對應設計 | SD-01、SD-02 |
| 實作狀態 | 已實作 |
| 優先級 | 高 |

**驗收條件**
- AC1（P-COM-01）：未登入時開啟首頁或任一功能頁，畫面會帶回登入頁。
- AC2（P-COM-03、P-COM-04）：任一測試帳號登入後均可看見相同功能；頁面顯示目前帳號，首頁另顯示角色。
- AC3（P-COM-05）：按「登出」後回到登入頁；再次開啟功能頁時須重新登入。

### US-COM-02 辨識頁面與導覽
**身為** Portal 使用者，**我想要** 在各頁看到一致的導覽與頁面標示，**以便** 快速找到所需功能並確認目前所在頁面。

| | |
|---|---|
| SRS 章節 | 3.2 |
| 涵蓋條文 | P-COM-07, P-COM-08, P-COM-09, P-COM-10, P-COM-11 |
| 對應設計 | SD-02 |
| 實作狀態 | 現況與條文不符 |
| 差異 | CSR 頁面的 HTML 頁面標題為「CSR 交易查詢」，SRS 規定為「CSR 查詢」。 |
| 優先級 | 中 |

**驗收條件**
- AC1（P-COM-07）：登入後頁首顯示「new-pay Portal」與目前帳號；首頁另顯示角色。
- AC2（P-COM-08、P-COM-09）：各功能頁提供相同的八個導覽連結，且不依登入帳號隱藏連結；登入頁只有 Portal 標題、沒有導覽連結。
- AC3（P-COM-10）：各頁面的瀏覽器頁面標題與 SRS 規定相同；CSR 頁面目前標題不符（現況如此）。
- AC4（P-COM-11）：頁面使用 SRS 規定的繁體中文字型、背景、內容區塊及按鈕樣式。

### US-COM-03 查詢並閱讀結果
**身為** Portal 使用者，**我想要** 在結果區查看查詢進度、資料與錯誤，**以便** 判斷查詢結果並採取後續行動。

| | |
|---|---|
| SRS 章節 | 3.3、3.4 |
| 涵蓋條文 | P-COM-15, P-COM-16, P-COM-17, P-COM-20, P-COM-22, P-COM-23, P-COM-24, P-COM-26, P-COM-27, P-COM-28, P-COM-29 |
| 對應設計 | SD-03～SD-08、AD-02、AD-03 |
| 實作狀態 | 已實作 |
| 優先級 | 高 |

**驗收條件**
- AC1（P-COM-20）：報表類查詢結果以表格呈現，表格下方顯示符合條件的總筆數。
- AC2（P-COM-22、P-COM-23）：結果最多顯示 10 筆；無資料時顯示空表格與「total rows: 0」。
- AC3（P-COM-24）：沒有值的欄位顯示「null」。
- AC4（P-COM-15、P-COM-16、P-COM-26、P-COM-27）：查詢開始後結果區顯示「查詢中...」；完成後以新回應取代。後端連線或查詢失敗時，結果區顯示系統回傳的錯誤文字。
- AC5（P-COM-17）：後端沒有回應時，結果區持續顯示「查詢中...」。
- AC6（P-COM-28）：等待回應時仍可再次按下查詢；結果區以最後到達的回應為準。
- AC7（P-COM-29）：結果表格使用 Portal 規定的淡藍表頭、灰色格線與白色資料列樣式。

### US-COM-04 輸入條件並了解資料呈現
**身為** Portal 使用者，**我想要** 依畫面提示輸入條件並看懂日期與金額，**以便** 正確解讀查詢結果。

| | |
|---|---|
| SRS 章節 | 3.5、3.6 |
| 涵蓋條文 | P-COM-30, P-COM-31, P-COM-32, P-COM-33, P-COM-34, P-COM-35, P-COM-36 |
| 對應設計 | SD-03～SD-08、AD-02、AD-04、AD-05 |
| 實作狀態 | 已實作 |
| 優先級 | 中 |

**驗收條件**
- AC1（P-COM-30）：畫面不會先阻止空白、超長或非預期字元的輸入；送出後依回應顯示結果。
- AC2（P-COM-31）：查詢條件含單引號等不受支援字元時，畫面顯示後端回傳的錯誤；欄位長度超限時，存檔畫面顯示失敗訊息。
- AC3（P-COM-32）：服務條款缺少生效日期或內容、銀行帳戶缺少銀行代碼或帳號時，存檔失敗並顯示回傳訊息。
- AC4（P-COM-33）：日期輸入 8 碼，例如 `20260916`；小時輸入 2 碼，例如 `09`；服務條款生效日期輸入 14 碼，例如 `20260916090000`，欄位均為文字輸入。
- AC5（P-COM-34）：報表中的交易時間以 14 碼台灣時間原樣呈現。
- AC6（P-COM-35）：報表選取某日 00 時至 23 時時，查詢範圍包含該日最後一秒。
- AC7（P-COM-36）：交易金額以新台幣元呈現；銀行帳戶可選新台幣 NTD 或美金 USD。

### US-RPT-01 設定交易報表條件
**身為** 營運人員或商家，**我想要** 設定交易報表的日期、時段與商家條件，**以便** 找到需要檢視的交易。

| | |
|---|---|
| SRS 章節 | 4.3 |
| 涵蓋條文 | P-RPT-01, P-RPT-02, P-RPT-09, P-RPT-12, P-RPT-13 |
| 對應設計 | SD-03、AD-02 |
| 實作狀態 | 已實作 |
