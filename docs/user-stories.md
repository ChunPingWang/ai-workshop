# new-pay Portal User Stories

> 需求來源：`docs/new-pay_Portal_SRS.md`（SRS 1.0，2026-10-07）。系統怎麼做到的技術細節（網址、參數、資料表欄位）一律見 `docs/SD.md`。
> 驗收條件（AC）括號內為其涵蓋的 SRS 條文編號；句尾標「（現況如此）」者為 SRS 明文規定、但看起來像缺陷的行為，測試時照現況驗證，不要當成待修項目。

## 角色

| 業務角色 | 說明 | 本版次測試帳號 |
|---|---|---|
| 營運人員（BO） | 查詢交易、退款報表與對帳結果 | sa / sa |
| 產品經理（PM） | 維護各商家的服務條款 | sa / sa |
| 財務人員（Finance BO） | 查詢對帳結果、（未來）審核商家銀行帳戶 | sa / sa |
| 商家（CP） | 查詢交易、退款報表，註冊收款銀行帳戶 | cp / cp |
| 客服人員（CSR） | 依用戶門號查詢交易與退款紀錄 | csr / csr |
| Portal 使用者 | 以上任一角色 | 任一 |

本版次系統不依角色限制功能，表中分工是業務上的分工（P-COM-03）。

## COM 共用

### US-COM-01 登入後才能使用 Portal 功能
**身為** Portal 使用者，**我想要** 只有登入後才能看到交易與帳務資料，**以便** 確保資料不被未登入的人看到。

| | |
|---|---|
| SRS 章節 | 3.1 |
| 涵蓋條文 | P-COM-01, P-COM-02, P-COM-03, P-COM-05, P-COM-06 |
| 對應設計 | SD-01、AD-01 |
| 實作狀態 | 已實作 |
| 優先級 | 高 |

**驗收條件**
- AC1（P-COM-01）：沒有登入就直接打開首頁或任何功能頁（交易報表、退款報表、對帳查詢、服務條款、銀行帳戶、CSR 查詢），會被帶回登入頁。
- AC2（P-COM-02）：功能頁已經開著、但登入已失效時，按「查詢」或「存檔」不會跳回登入頁，而是在結果區或訊息區顯示「please login」；服務條款查詢會當成商家沒有條款，銀行帳戶清單會變成只有表頭的空表格（現況如此）。
- AC3（P-COM-03）：營運人員、商家、客服人員任一身分登入後，都能打開全部功能頁並執行查詢與存檔，系統不依身分限制功能（現況如此）。
- AC4（P-COM-05）：按「登出」後回到登入頁；之後再打開功能頁會被帶回登入頁，在已開著的頁面按查詢則顯示「please login」。
- AC5（P-COM-06）：閒置超過 30 分鐘沒有操作，登入即失效，需重新登入；同一個帳號可以同時在多個瀏覽器登入使用。

| 對應設計 | SD-02 |
| 實作狀態 | 已實作 |
| 優先級 | 中 |

**驗收條件**
- AC1（P-COM-07, P-COM-04）：登入後每一頁頂端都有深藍色導覽列，左側顯示「new-pay Portal | 我的帳號」；只有首頁會在帳號後再加上「(角色)」。
- AC2（P-COM-08）：導覽列依序有 8 個連結：首頁、交易報表、退款報表、對帳查詢、服務條款、銀行帳戶、CSR查詢、登出，每一頁都相同；登入頁的標題列只有「new-pay Portal」文字，沒有任何連結。
- AC3（P-COM-09）：不論以哪種身分登入，導覽列的連結都一樣，不會隱藏任何功能（現況如此）。
- AC4（P-COM-10）：瀏覽器分頁標題：登入頁「new-pay Portal 登入」、首頁「new-pay Portal」、交易報表與退款報表都是「交易報表查詢」、對帳「OLS 對帳結果查詢」、服務條款「服務條款設定」、銀行帳戶「商家銀行帳戶註冊」、CSR「CSR 交易查詢」。
- AC5（P-COM-11）：中文正常顯示；頁面底色為淡灰藍、內容區塊為白底灰框、提示文字為紅色小字、按鈕為深藍底白字。
- AC6（P-COM-12）：電腦無法連上外部網路時，各頁面的版面與按鈕功能仍正常，不依賴外部資源。

### US-COM-03 閱讀報表類查詢結果
**身為** Portal 使用者，**我想要** 每種報表的結果都以一致的表格呈現並告訴我總筆數，**以便** 快速判讀查詢結果、知道是否還有未顯示的資料。

| | |
|---|---|
| SRS 章節 | 3.4、3.6 |
| 涵蓋條文 | P-COM-20, P-COM-21, P-COM-22, P-COM-23, P-COM-24, P-COM-25, P-COM-27, P-COM-28, P-COM-29, P-COM-34, P-COM-36 |
| 對應設計 | SD-03、AD-02 |
| 實作狀態 | 已實作 |
| 優先級 | 高 |

適用於交易報表、退款報表、對帳查詢、對帳差異明細與 CSR 查詢。

**驗收條件**
- AC1（P-COM-27）：按下「查詢」後，結果區先顯示「查詢中...」，結果回來後整個結果區換成新內容。
- AC2（P-COM-20, P-COM-29）：結果以表格呈現：第一列是淡藍底的表頭，之後每筆資料一列，有灰色格線、白底；表格下方顯示「total rows: N」。
- AC3（P-COM-21）：表頭顯示英文大寫的欄位代號（例如 TXID、AMOUNT），不翻成中文（現況如此）。
- AC4（P-COM-22）：表格最多列出 10 筆；「total rows: N」的 N 是符合條件的全部筆數，可能大於 10。
- AC5（P-COM-23）：查無資料時只顯示一個沒有表頭、沒有資料列的空表格，以及「total rows: 0」。
- AC6（P-COM-24）：沒有值的欄位顯示文字「null」，例如尚未請款之交易的請款時間。
- AC7（P-COM-25）：資料內容原樣顯示，不做任何轉換；資料中若含網頁標記語法，會被瀏覽器當成格式呈現（現況如此）。
- AC8（P-COM-28）：等待結果期間「查詢」按鈕仍可再按；連按多次會送出多次查詢，結果區以最後回來的結果為準（現況如此）。
- AC9（P-COM-34）：時間欄位以 14 碼數字原樣顯示台灣時間，例如 20260916235959，不另加分隔符號。
- AC10（P-COM-36）：金額為整數（新台幣元），交易的幣別顯示 TWD；銀行帳戶的幣別為 NTD 或 USD。

### US-COM-04 後端異常時看到錯誤訊息
**身為** Portal 使用者，**我想要** 系統出問題時畫面上有明確的錯誤訊息，**以便** 知道不是「查無資料」，並能回報給維運人員。

| 涵蓋條文 | P-COM-13, P-COM-14, P-COM-15, P-COM-16, P-COM-17, P-COM-18, P-COM-19, P-COM-26 |
| 對應設計 | SD-03、AD-03 |
| 實作狀態 | 已實作 |
| 優先級 | 高 |

**驗收條件**
- AC1（P-COM-15）：後端服務沒有啟動或發生錯誤時，按「查詢」後結果區顯示以「backend error: 」開頭的錯誤訊息。
- AC2（P-COM-16）：存檔或註冊時後端無法處理，訊息區顯示以「FAIL 」開頭的錯誤訊息。
- AC3（P-COM-26）：查詢條件造成資料查詢錯誤時，結果區顯示以「query error: 」開頭的訊息，並附上系統的查詢語句（現況如此）。
- AC4（P-COM-17）：後端遲遲沒有回應時，結果區會一直停在「查詢中...」，系統不會逾時提示（現況如此）。
- AC5（P-COM-13, P-COM-14, P-COM-18, P-COM-19）：Portal 把查詢與存檔轉送給後端的方式，系統行為依 SD-03、AD-03 所述（技術規格）。

### US-COM-05 輸入查詢與存檔條件
**身為** Portal 使用者，**我想要** 清楚知道各欄位該怎麼輸入、輸入錯了會發生什麼事，**以便** 查到正確的資料、存檔不出錯。

| | |
|---|---|
| SRS 章節 | 3.5、3.6 |
| 涵蓋條文 | P-COM-30, P-COM-31, P-COM-32, P-COM-33, P-COM-35 |
| 對應設計 | AD-02、AD-03 |
| 實作狀態 | 現況與條文不符 |
| 優先級 | 中 |

> 差異：P-COM-31 規定輸入含單引號時「查詢回 query error」。但服務條款查詢與銀行帳戶清單的商家代碼含單引號時，後端是直接發生系統錯誤（不是 query error），畫面不更新、也沒有任何訊息（詳見 SD-06、SD-07）。

**驗收條件**
- AC1（P-COM-33）：日期輸入 8 碼，例如 20260916；報表的小時用下拉選 00～23；服務條款生效日期輸入 14 碼，例如 20261001000000。都是文字框，沒有日曆可以點選。
- AC2（P-COM-30）：畫面不檢查輸入格式，欄位可以留空、長度與字元不限，按下查詢或存檔就照原樣送出，結果依系統回應而定（現況如此）。
- AC3（P-COM-31）：輸入內容含單引號（'）時，查詢顯示「query error: …」、存檔顯示「FAIL …」；輸入超過欄位長度時存檔顯示「FAIL …」（現況如此）。
- AC4（P-COM-32）：必填欄位（服務條款的生效日期與內容、銀行帳戶的銀行代碼與帳號）留空就存檔，會顯示「FAIL …」，訊息含「NULL not allowed」。
- AC5（P-COM-35）：查 9/16 的 00 時到 23 時，結果包含 9/16 00:00:00 到 23:59:59 的資料，頭尾兩端都算在內。

## RPT 交易報表

### US-RPT-01 開啟交易報表並設定查詢條件
**身為** 營運人員或商家，**我想要** 打開交易報表時就帶好常用的預設條件，**以便** 不用每次重打就能查今天的交易。

| | |
|---|---|
| SRS 章節 | 4.3 |
| 涵蓋條文 | P-RPT-01, P-RPT-02, P-RPT-03, P-RPT-12 |
| 對應設計 | SD-03 |
| 實作狀態 | 已實作 |
| 優先級 | 中 |

**驗收條件**
- AC1（P-RPT-01）：打開交易報表，日期(起)與日期(迄)預設為今天（依使用者電腦上的日期），小時預設 00 到 23，商家預設 E000001，時間類型預設「交易時間」，結果區顯示「請輸入條件查詢」。
- AC2（P-RPT-02）：起、迄兩個「時」下拉各有 24 個選項：00、01……23。
- AC3（P-RPT-03）：查詢區間為「起日＋起始時」到「迄日＋結束時」，頭尾都算；小時選 00 到 23 即代表整天，例如查 9/16 的 00 時到 23 時會包含 9/16 23:59:59 那一筆。
- AC4（P-RPT-12）：只要不是指定退款報表，從任何連結或網址進入報表頁都顯示交易報表。

### US-RPT-02 查詢並閱讀交易明細
**身為** 營運人員或商家，**我想要** 依日期、時段與商家查出交易明細，**以便** 掌握每天的收款狀況。

| | |
|---|---|
| SRS 章節 | 4.3 |
| 涵蓋條文 | P-RPT-04, P-RPT-05, P-RPT-06, P-RPT-07, P-RPT-08, P-RPT-10, P-RPT-13 |
| 對應設計 | SD-03、AD-02 |
| 實作狀態 | 已實作 |
| 優先級 | 高 |

**驗收條件**
- AC1（P-RPT-04）：時間類型選「交易時間」時以交易建立時間篩選；選「授權時間(只限OLS)」時以 OLS 授權時間篩選，非 OLS 交易沒有授權時間，不會被查出。

**身為** 商家，**我想要** 在註冊頁填寫收款銀行帳戶的資料，**以便** 準備送出註冊。

| | |
|---|---|
| SRS 章節 | 4.7 |
| 涵蓋條文 | P-BNK-01, P-BNK-03, P-BNK-14 |
| 對應設計 | SD-07、AD-05 |
| 實作狀態 | 已實作 |
| 優先級 | 中 |

**驗收條件**
- AC1（P-BNK-01）：打開銀行帳戶頁，商家代碼預設 E000001，銀行代碼與銀行帳號空白，匯款幣別預設「新台幣(NTD)」，「外國銀行」未勾選，訊息區與清單區都是空的。
- AC2（P-BNK-03）：匯款幣別只有「新台幣(NTD)」與「美金(USD)」兩個選項，存入的幣別即所選的 NTD 或 USD。
- AC3（P-BNK-14）：商家代碼可自由輸入，系統不限制商家只能註冊自己的帳戶（現況如此）。

### US-BNK-02 註冊收款銀行帳戶
**身為** 商家，**我想要** 註冊我的收款銀行帳戶，**以便** new-pay 日後撥款到這個帳戶。

| | |
|---|---|
| SRS 章節 | 4.7 |
| 涵蓋條文 | P-BNK-02, P-BNK-04, P-BNK-08, P-BNK-10, P-BNK-13 |
| 對應設計 | SD-07、AD-05 |
| 實作狀態 | 已實作 |
| 優先級 | 高 |

**驗收條件**
- AC1（P-BNK-02）：填好銀行代碼與帳號後按「註冊」，訊息顯示「OK」，下方清單自動刷新並出現新帳戶，狀態欄為 W（待審核）。
- AC2（P-BNK-04）：勾選「外國銀行」註冊的帳戶在清單顯示「國外」，未勾選的顯示「國內」。
- AC3（P-BNK-08）：系統不檢查銀行代碼與帳號是否為數字、不檢查商家是否存在、也不檢查重複；同樣的資料再註冊一次會出現兩筆（現況如此）。
- AC4（P-BNK-10）：註冊訊息不會因為清單刷新而消失；再次註冊時換成新的訊息。
- AC5（P-BNK-13）：本版次沒有財務審核功能，新註冊的帳戶一直維持 W；畫面固定提示「送出後由 Finance 於 SA Portal 審核 (審核作業尚未提供, 狀態先掛 W)」。

### US-BNK-03 查詢已註冊的銀行帳戶
**身為** 商家，**我想要** 查看已註冊的銀行帳戶與審核狀態，**以便** 確認帳戶資料正確、是否已核准。

| | |
|---|---|
| SRS 章節 | 4.7 |
| 涵蓋條文 | P-BNK-05, P-BNK-06, P-BNK-09, P-BNK-12 |
| 對應設計 | SD-07 |
| 實作狀態 | 已實作 |
| 優先級 | 中 |

**驗收條件**
- AC1（P-BNK-05）：按「查詢已註冊帳戶」，清單以中文表頭顯示 6 欄：商家、銀行代碼、帳號、幣別、國內外、狀態；沒有資料時只有表頭列，也沒有「total rows」。
- AC2（P-BNK-06）：清單列出該商家代碼（須完全相符）的全部帳戶，不限 10 筆，依註冊先後排列。
- AC3（P-BNK-09）：狀態以代碼顯示（W 待審核、A 已核准），不轉中文；畫面沒有審核、刪除、修改功能。
- AC4（P-BNK-12）：系統初始已有 E000001 的一筆帳戶：銀行 007、帳號 1234567890123456、USD、國外、狀態 A。

### US-BNK-04 銀行帳戶註冊失敗與異常
**身為** 商家，**我想要** 註冊失敗時看到訊息，**以便** 修正資料後重新註冊。

| | |
|---|---|
| SRS 章節 | 4.7 |
| 涵蓋條文 | P-BNK-07, P-BNK-11 |
| 對應設計 | SD-07、AD-05 |
| 實作狀態 | 已實作 |
| 優先級 | 中 |

**驗收條件**
- AC1（P-BNK-07）：銀行代碼超過 3 碼或銀行帳號超過 16 碼時，訊息顯示「FAIL …」（含「Value too long」），清單仍會自動刷新。
- AC2（P-BNK-07）：銀行代碼或銀行帳號空白時註冊失敗，顯示「FAIL …」。
- AC3（P-BNK-11）：後端無法連線時查詢清單，清單不更新，也沒有任何訊息（現況如此）。
- AC4（P-BNK-11）：登入已失效時註冊，訊息顯示「please login」，清單變成只有表頭的空表格。

## CSR 客服查詢

### US-CSR-01 輸入門號查詢用戶交易
**身為** 客服人員，**我想要** 輸入用戶的門號就查到他的交易，**以便** 在電話中立即回答用戶。

| | |
|---|---|
| SRS 章節 | 4.8 |
| 涵蓋條文 | P-CSR-01, P-CSR-02, P-CSR-08 |
| 對應設計 | SD-08 |
| 實作狀態 | 已實作 |
| 優先級 | 高 |

**驗收條件**
- AC1（P-CSR-01）：打開 CSR 查詢，門號預設 0912345678，結果區顯示「請輸入門號查詢」。
- AC2（P-CSR-02）：按「查詢」後結果區先顯示「查詢中...」，接著列出該門號（須完全相符）在所有管道的交易，不限 OLS。
- AC3（P-CSR-08）：門號留空或格式不對（不是 10 碼、含英文）仍會查詢，結果為 0 筆，系統不提示（現況如此）。

### US-CSR-02 閱讀用戶的交易與退款紀錄
**身為** 客服人員，**我想要** 同一畫面看到用戶的交易與退款紀錄，**以便** 回答用戶對扣款與退款的詢問。

| | |
|---|---|
| SRS 章節 | 4.8 |
| 涵蓋條文 | P-CSR-03, P-CSR-04, P-CSR-05, P-CSR-06, P-CSR-09 |
| 對應設計 | SD-08 |
| 實作狀態 | 已實作 |
| 優先級 | 高 |

**驗收條件**
- AC1（P-CSR-03）：上方交易表 8 欄，依序為交易序號、金額、交易狀態、交易時間、授權時間、商品名稱、商家聯絡資訊、回應代碼；最新的交易排在最上面。
- AC2（P-CSR-04）：商品名稱即 OLS 的 PaymentDescription（最多 60 字），商家聯絡資訊即 MerchantContact。
- AC3（P-CSR-05）：交易表下方有一條分隔線與文字「Refunds:」，接著是退款表 8 欄，依序為交易序號、商家、退款金額、退款狀態、退款時間、建立時間、回應代碼、回應訊息；列出該門號任一筆交易的退款，不排序。
- AC4（P-CSR-06）：兩個表各自最多顯示 10 筆，並各有自己的「total rows: N」。
- AC5（P-CSR-09）：交易狀態、退款狀態與回應代碼以代碼原樣顯示；沒有值時顯示「null」，例如未取消的交易其回應代碼為 null。

### US-CSR-03 客服查詢查無資料與異常
**身為** 客服人員，**我想要** 查無資料與系統異常時有明確的呈現，**以便** 正確告知用戶。

| | |
|---|---|
| SRS 章節 | 4.8 |
| 涵蓋條文 | P-CSR-07, P-CSR-10 |
| 對應設計 | SD-08、AD-03 |
| 實作狀態 | 已實作 |
| 優先級 | 中 |

**驗收條件**
- AC1（P-CSR-07）：門號查無交易時，兩個表都是空表格與「total rows: 0」，中間仍有分隔線與「Refunds:」；有交易但沒有退款時，只有下方退款表是空的。
- AC2（P-CSR-10）：後端無法連線時結果區顯示「backend error: …」。
- AC3（P-CSR-10）：查詢發生錯誤（例如門號含單引號）時顯示「query error: …」；交易與退款兩段各自判斷，可能只有其中一段出錯。
